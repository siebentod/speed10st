# speed10st

Консольный скрипт на Node.js: делает 10 последовательных запросов к указанному адресу, полностью скачивает каждый ответ и печатает статистику.

## Требования

- Node.js **18 или новее** (используется встроенный `fetch`)
- Внешние зависимости не нужны

## Запуск

```bash
node main.js <url>
# или
npm start -- <url>
```

Пример:

```bash
node main.js https://example.com/big-image.jpg
```

Пример вывода:

```
URL:                  https://example.com/big-image.jpg
Requests:             10
Average request time: 412.37 ms
Total downloaded:     48.20 MB (48201234 bytes)
Download speed:       93.52 Mbit/s
```

## Что и как считается

| Метрика | Формула | Единицы |
| --- | --- | --- |
| Среднее время запроса | сумма длительностей всех запросов / 10 | миллисекунды (ms) |
| Общий объём данных | сумма размеров тел всех ответов | мегабайты (MB), 1 MB = 10^6 байт; в скобках точное число байт |
| Скорость скачивания | общий объём в битах / суммарное время запросов | **мегабиты в секунду (Mbit/s)**, 1 Mbit = 10^6 бит |

### Почему Mbit/s

Скорость каналов связи принято измерять в мегабитах в секунду. Так результат напрямую сопоставим с тарифом провайдера и с результатами speedtest-сервисов. Для перевода в мегабайты в секунду разделите значение на 8.

### Детали измерения

- **Длительность запроса** отсчитывается от начала `fetch` до момента, когда тело ответа получено полностью. В неё входят DNS, TCP/TLS-рукопожатие (на первом запросе), ожидание ответа и передача данных.
- **Скорость** считается как суммарный объём, делённый на суммарное время запросов, а не как среднее скоростей отдельных запросов. Так крупные и медленные запросы вносят в результат пропорциональный вклад. Паузы между запросами в расчёт не входят.
- **Размер** считается по реально полученным байтам тела ответа. Скрипт отправляет `Accept-Encoding: identity`, поэтому сервер не сжимает данные, а счётчик не искажается прозрачной распаковкой. Заголовки ответа в объём не входят.
- Тело читается потоком и не накапливается в памяти, поэтому скрипт работает одинаково на файлах любого размера.
- Соединения между запросами могут переиспользоваться (keep-alive), как в обычном клиенте: первый запрос включает установку соединения, последующие обычно нет.
- Редиректы обрабатываются автоматически, учитывается размер финального ответа.

## Ошибки

Если любой из запросов завершился ошибкой (невалидный URL, сетевая ошибка, статус не 2xx, таймаут 60 с), скрипт прекращает работу, печатает причину в `stderr` и завершается с кодом `1`. Частичная статистика не выводится, чтобы не вводить в заблуждение.

## Тесты

Тесты написаны на [Vitest](https://vitest.dev/) и работают без доступа в интернет: внутри поднимается локальный HTTP-сервер на случайном порту.

```bash
npm install
npm test
```

Что проверяется:

- разбор и валидация URL (пустой аргумент, невалидная строка, не-http протокол);
- `download` возвращает точный размер тела и положительную длительность, а на ответе не-2xx завершается ошибкой;
- `runBenchmark` делает ровно 10 запросов и никогда не выполняет два одновременно;
- расчёт среднего времени, общего объёма и скорости, включая проверку, что скорость взвешена по объёму.

Vitest 3 нужен только для разработки, сам скрипт работает без зависимостей.
